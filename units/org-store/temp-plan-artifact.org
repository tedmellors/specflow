#+TITLE: org-store – Plan Artifact: Task Management Commands
#+DATE: [2026-01-20]

* Summary

Adding two task management commands to org-store:

1. =specflow-refine-task= — Generate prompt for Claude to improve a backlog task
2. =specflow-activate-task= — Same + promote to NEXT, demote current NEXT

* Command Designs

** specflow-refine-task

Interactive workflow:
1. Display backlog tasks via =completing-read=
2. Prompt: "Related unit (or none):" with unit names + "none" option
3. Prompt: "Additional context for Claude:"
4. Generate prompt and copy to kill-ring
5. Display confirmation message

Prompt output structure:
#+begin_example
## Task to Refine

<task headline and body>

## Related Unit Context

Unit: <unit-name>
Phase: <current phase>
Parent chain: <ancestors>
Spec summary: <first ~10 lines of spec or "See full spec at path">

## Your Instructions

<user's comment>

## Guidelines

Rewrite this task to be actionable and outcome-based:
- Use Given/When/Then format where appropriate
- Be specific about expected outcomes
- Include acceptance criteria if possible
- Keep it concise (3-5 bullets max)

Return only the revised task text.
#+end_example

** specflow-activate-task

Same as =specflow-refine-task=, plus:

After generating prompt:
1. Find current NEXT task in Active section
2. Change NEXT → TODO (keep in Active section)
3. Move selected task from Backlog to Active section
4. Change TODO → NEXT on selected task
5. Display confirmation: "Task activated: <headline>"

* Implementation Notes

** Reading backlog tasks

Need new helper to parse tasks from Backlog section:
- Find "* Backlog" heading
- Extract all level-2 headings with their bodies
- Return list of (headline . body) pairs

** Writing task state changes

Use existing =specflow-org-store-write-property= pattern but for TODO state:
- Need new helper to change TODO keyword on a heading
- Or use simple regex replacement (minimal-diff)

** Unit context assembly

If user selects a unit:
- Use =specflow-org-store-read-unit= to get unit entry
- Use =specflow-org-store-validate-parent-chain= for ancestors
- Read first N lines of spec file for summary

* Design Decisions

1. User selects unit manually (no auto-detection)
2. User can add free-form comment for Claude
3. Demoted NEXT stays in Active section (not moved to Backlog)
4. Prompt goes to kill-ring (consistent with other commands)

* Tests Required

** specflow-refine-task tests
- Lists backlog tasks correctly
- Handles "none" unit selection
- Includes user comment in prompt
- Copies prompt to kill-ring

** specflow-activate-task tests
- Demotes current NEXT to TODO
- Promotes selected task to NEXT
- Moves task from Backlog to Active
- Handles case with no current NEXT
