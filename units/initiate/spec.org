#+TITLE: initiate – Specification
#+STARTUP: overview

* Purpose

=initiate= bootstraps new SpecFlow projects.

When a developer starts a new project and wants to use SpecFlow, they run
=specflow-initiate= in the project directory. This creates the minimal file
structure needed to begin SpecFlow-driven development.

Target user: Developer starting a new project who wants SpecFlow scaffolding.

* Scope

**In scope**
- Create control plane (=docs/specflow.org=) with starter template
- Create root =CLAUDE.md= with SpecFlow rules for AI assistants
- Create root =todo.org= with example NEXT task
- Create =.specflow= marker file for project detection
- Validate directory is appropriate (not already a SpecFlow project)

**Out of scope**
- Defining unit specifications (user does this later)
- Creating unit directories beyond core
- Git initialization
- Interactive prompts for customization (MVP)
- Project naming (derives from directory name)

* Public Commands

** specflow-initiate

Interactive command that creates SpecFlow scaffolding in the current directory.

#+begin_example
M-x specflow-initiate
#+end_example

*** Preconditions

1. Current directory must not already contain =docs/specflow.org=
2. Current directory must not already contain =.specflow= marker

If preconditions fail, display error and do not create files.

*** Files Created

| File | Purpose |
|------|---------|
| =docs/specflow.org= | Control plane |
| =CLAUDE.md= | Root AI assistant rules |
| =todo.org= | Root task driver |
| =.specflow= | Project marker (empty file) |
| =units/core/= | Core unit directory (empty) |

*** Behavior

1. Check preconditions
2. Create =docs/= directory if not exists
3. Write =docs/specflow.org= from template
4. Write root =CLAUDE.md= from template
5. Write root =todo.org= from template
6. Create =.specflow= marker file
7. Create =units/core/= directory
8. Display success message with next steps

* File Templates

** docs/specflow.org (Control Plane)

#+begin_example
#+TITLE: <project-name> – Control Plane
#+STARTUP: overview
#+SEQ_TODO: TODO NEXT WAITING | DONE

* Project
  :PROPERTIES:
  :SPEC_FLOW_PHASE: Plan
  :SPEC_FLOW_ACTIVE_UNIT: core
  :END:

This is the SpecFlow control plane for <project-name>.

* Units

** core
   :PROPERTIES:
   :DIR: src/
   :SPEC: units/core/spec.org
   :TODO: units/core/todo.org
   :RULES: units/core/CLAUDE.md
   :END:

The core unit defines project-level architecture and constraints.
#+end_example

Where =<project-name>= is derived from the directory name.

** CLAUDE.md (Root Rules)

#+begin_example
# <project-name> – AI Assistant Rules

## SpecFlow Project

This repository uses SpecFlow: a spec-driven, phase-gated workflow
for AI-assisted software development.

## Control Plane

The current operational state is defined in:
- `docs/specflow.org` (control plane)

Before starting any work:
1. Read the control plane
2. Identify the active unit and phase
3. Follow the phase rules

## Phase Enforcement

Phases: Plan → Specify → Scaffold → Implement → Validate → Document

- **Plan**: Design only. No code, no specs.
- **Specify**: Edit spec.org only.
- **Scaffold**: Write CLAUDE.md and todo.org only.
- **Implement**: Write code and tests per spec.
- **Validate**: Verify behavior. No changes.
- **Document**: Write documentation only.

## Task Discovery

The canonical NEXT task is in `todo.org` at the repo root.

## Stop Conditions

STOP and ask for confirmation if:
- Action would violate the current phase
- Interface change is required
- Scope creep is detected
#+end_example

* Error Handling

| Condition | Behavior |
|-----------|----------|
| =docs/specflow.org= exists | Error: "SpecFlow project already exists" |
| =.specflow= marker exists | Error: "SpecFlow project already exists" |
| Cannot create directory | Signal file error |
| Cannot write file | Signal file error |

* Non-Functional Requirements

- **Fast**: Completes in under 1 second
- **Idempotent detection**: Refuses to overwrite existing project
- **Minimal**: Creates only essential files
- **Self-documenting**: Created files explain SpecFlow workflow

* Success Criteria

Given a developer in a new project directory,
when they run =specflow-initiate=,
then:
- Control plane exists at =docs/specflow.org=
- Root =CLAUDE.md= contains SpecFlow rules
- Root =todo.org= contains example NEXT task
- =.specflow= marker exists
- =units/core/= directory exists
- They can immediately use other SpecFlow commands

* Dependencies

- None (initiate is standalone)
- Uses basic Emacs file operations only
