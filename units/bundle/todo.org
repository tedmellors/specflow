* Implement

** DONE Core: specflow-bundle-context
   CLOSED: [2025-01-19]
   Given a SpecFlow project with control plane and units,
   when =specflow-bundle-context= is called with no arguments,
   then it returns a string containing the formatted context bundle.

   Outcomes:
   - Reads project state via org-store
   - Extracts NEXT task from root todo.org
   - Resolves parent chain via org-store
   - Splits space-separated SPEC/TODO/RULES into file lists
   - Reads and includes content from each file
   - Formats output with section delimiters per spec
   - Returns deterministic output (except timestamp)

** DONE Core: specflow-bundle-context with unit-name
   CLOSED: [2025-01-19]
   Given a unit name argument,
   when =specflow-bundle-context= is called with UNIT-NAME,
   then it bundles context for that unit instead of the active unit.

   Outcomes:
   - Uses provided UNIT-NAME instead of active unit
   - Signals =specflow-unit-not-found= if unit not in registry

** DONE NEXT extraction: specflow-bundle--extract-next-task
   CLOSED: [2025-01-19]
   Given a root todo.org file,
   when =specflow-bundle--extract-next-task= is called,
   then it returns the first NEXT heading with its content.

   Outcomes:
   - Finds first heading marked NEXT (any level)
   - Extracts heading title and body until next heading
   - Returns placeholder if no NEXT found
   - Does NOT signal error for missing NEXT

** DONE File reading: specflow-bundle--read-file-content
   CLOSED: [2025-01-19]
   Given a file path (absolute or relative to project root),
   when =specflow-bundle--read-file-content= is called,
   then it returns the file content as a string.

   Outcomes:
   - Returns file content if file exists
   - Returns placeholder =<file not found: PATH>= if missing
   - Logs warning for missing files
   - Does NOT signal error for missing files

** DONE Property splitting: specflow-bundle--split-paths
   CLOSED: [2025-01-19]
   Given a property value string (potentially space-separated),
   when =specflow-bundle--split-paths= is called,
   then it returns a list of individual paths.

   Outcomes:
   - Single path returns single-element list
   - Space-separated paths return multi-element list
   - Empty/nil returns empty list

** DONE Formatting: specflow-bundle--format-output
   CLOSED: [2025-01-19]
   Given project state, NEXT task, parent chain content, and unit content,
   when =specflow-bundle--format-output= is called,
   then it returns the formatted bundle string.

   Outcomes:
   - Header with timestamp
   - Project state section
   - NEXT task section
   - Parent sections (root-to-leaf order)
   - Unit sections (SPEC, TODO, RULES)
   - Each file has labeled subsection

   - =(specflow-bundle-context nil :spec-only t)= — just specs, no todos/rules
   - =(specflow-bundle-context nil :active-only t)= — just the active unit

   Proposed UI:
   - A transient menu for =M-x specflow-bundle= with checkboxes

   - For incremental work: selective options reduce noise
