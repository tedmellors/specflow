#+TITLE: bundle – Specification
#+STARTUP: overview

* Purpose

bundle is the SpecFlow module responsible for assembling context bundles
for AI assistants. When a developer needs to provide context to an AI
(e.g., Claude, GPT), bundle gathers all relevant project files into a
single, deterministic output.

All context reading is done via the org-store API.

* Scope

** Owns
- Assembling context from control plane, root todo, and unit files
- Resolving parent chain and including ancestor content
- Splitting space-separated property values (SPEC, TODO)
- Formatting output with section delimiters
- Interactive command for bundling (M-x specflow-bundle)
- Output to kill-ring and buffer

** Does Not Own
- Control plane discovery or parsing (org-store)
- Property writing (org-store)
- LLM compression (deferred)
- CONTEXT_REFS resolution (deferred)
- UI/workspace management (hydrate)

* Bundle Contents

The context bundle includes (in order):

| Content | Source | Notes |
|-----------------+--------------------------------+-------------------------------|
| Project state | Control plane | Phase, active unit |
| NEXT task | .specflow/todo.org | First NEXT heading + bullets |
| Parent chain | Each ancestor (root-to-leaf) | SPEC, TODO files |
| Active unit | Current unit | SPEC, TODO files |

** Parent Chain Order

Parent chain is presented root-to-leaf (most general first, most specific last).
For example, if bundle's parent is core, the output shows core's files first,
then bundle's files.

** Property Splitting

SPEC and TODO properties may contain space-separated paths:

#+begin_example
:SPEC: .specflow/units/core/architecture.org .specflow/units/core/overview.org
#+end_example

Bundle splits these into a list and reads each file.

* Output Modes

Bundle supports two output modes optimized for different AI tools:

| Mode | Command | Output | Use Case |
|------+-----------------------+--------------+------------------------------|
| Paths | =M-x specflow-bundle= | File paths | Claude Code (can read files) |
| Text | =M-x specflow-bundle-text= | Full content | gptel, web Claude, external |

** Paths Mode (Default)

Outputs file paths that Claude Code can read directly. More efficient for
tools with file access (~20 lines vs ~600 lines).

#+begin_example
# SpecFlow Context Bundle (Paths)
# Generated: 2025-01-19T15:30:00

## Project State
Phase: Plan
Active Unit: bundle

## NEXT Task
** NEXT bundle: Document phase
   <full NEXT task content included - typically short>

## Parent: core
- SPEC: .specflow/units/core/architecture.org
- SPEC: .specflow/units/core/overview.org
- TODO: .specflow/units/core/todo.org

## Unit: bundle
- SPEC: .specflow/units/bundle/spec.org
- TODO: .specflow/units/bundle/todo.org

Read the files above for full context.
#+end_example

** Text Mode

Outputs full file contents. Use for AI tools without file access.

#+begin_example
# SpecFlow Context Bundle (Text)
# Generated: 2025-01-19T15:30:00

## Project State
Phase: Plan
Active Unit: bundle

## NEXT Task
<content of first NEXT heading from .specflow/todo.org>

## Parent: core

### SPEC: .specflow/units/core/architecture.org
<file content>

### SPEC: .specflow/units/core/overview.org
<file content>

### TODO: .specflow/units/core/todo.org
<file content>

## Unit: bundle

### SPEC: .specflow/units/bundle/spec.org
<file content>

### TODO: .specflow/units/bundle/todo.org
<file content>
#+end_example

** Missing Files

If a referenced file does not exist:
- Log a warning (message)
- Include placeholder in output: =<file not found: path/to/file>=
- Do NOT signal an error (bundle should be resilient)

* Public API

** specflow-bundle-context (Paths Mode)

#+begin_example
(specflow-bundle-context &optional UNIT-NAME)
#+end_example

- Input: UNIT-NAME (optional, defaults to active unit from control plane)
- Output: String containing file paths bundle (default mode)
- Errors:
  - =specflow-control-plane-not-found= if control plane missing
  - =specflow-unit-not-found= if specified unit not in registry

** specflow-bundle-context-text (Text Mode)

#+begin_example
(specflow-bundle-context-text &optional UNIT-NAME)
#+end_example

- Input: UNIT-NAME (optional, defaults to active unit from control plane)
- Output: String containing full file contents bundle
- Errors: Same as =specflow-bundle-context=

** specflow-bundle (Interactive Command - Paths)

#+begin_example
M-x specflow-bundle
#+end_example

Interactive command that:
1. Calls =specflow-bundle-context= for the active unit (paths mode)
2. Copies result to kill-ring
3. Opens result in a new buffer named =*SpecFlow Bundle*=
4. Displays message confirming bundle is ready

Use this for Claude Code and other AI tools with file access.

** specflow-bundle-text (Interactive Command - Text)

#+begin_example
M-x specflow-bundle-text
#+end_example

Interactive command that:
1. Calls =specflow-bundle-context-text= for the active unit (text mode)
2. Copies result to kill-ring
3. Opens result in a new buffer named =*SpecFlow Bundle*=
4. Displays message confirming bundle is ready

Use this for gptel, web Claude, and AI tools without file access.

* NEXT Task Extraction

The NEXT task is extracted from =.specflow/todo.org=:

1. Find the first heading marked =NEXT= (any level)
2. Extract the heading title and all content until the next heading
3. Include sub-items, bullets, and body text
4. Stop at the next same-level or higher-level heading

If no NEXT task is found:
- Include placeholder: =<no NEXT task found>=
- Do NOT signal an error

* Determinism

Running =specflow-bundle-context= twice without repo changes MUST produce
identical output, EXCEPT for the timestamp in the header.

For testing purposes, a =specflow-bundle-context-no-timestamp= variant
may be provided that omits the timestamp for determinism tests.

* Error Handling

** Hard Failures (signal error)

| Error Symbol | Condition |
|----------------------------------+--------------------------------------|
| =specflow-control-plane-not-found= | Control plane discovery failed |
| =specflow-unit-not-found= | Specified unit not in registry |

** Soft Failures (warning, continue)

| Condition | Behavior |
|-------------------------+----------------------------------------|
| File in SPEC/TODO | Placeholder in output, log warning |
| not found | |
| No NEXT task found | Placeholder in output |
| Empty file | Include empty section |

* Dependencies

- org-store: =specflow-org-store-find-control-plane=
- org-store: =specflow-org-store-read-project-state=
- org-store: =specflow-org-store-read-unit=
- org-store: =specflow-org-store-validate-parent-chain=

Does NOT depend on:
- core (no shared constants needed in MVP)
- hydrate
- LLM integration

* Testing Requirements

** ERT Test Coverage

*** Paths Mode
- Bundle returns file paths, not full content
- Paths mode output is compact (~20 lines)
- NEXT task content is included (not just path)
- Parent chain paths listed correctly
- Unit paths listed correctly

*** Text Mode
- Bundle returns full file contents
- Text mode output includes all file content
- Bundle with single-file SPEC/TODO
- Bundle with space-separated multi-file SPEC
- Bundle with parent chain (single parent)

*** Both Modes
- Bundle with missing file (soft failure)
- Bundle with no NEXT task (soft failure)
- Determinism: bundle twice, compare output (excluding timestamp)
- Interactive commands place content in kill-ring and buffer

** Manual Smoke Test

- M-x specflow-bundle in a SpecFlow project (paths mode)
- M-x specflow-bundle-text in a SpecFlow project (text mode)
- Verify paths mode output is compact with file paths
- Verify text mode output includes full content
- Verify kill-ring contains the bundle
- Verify buffer displays correctly

* Non-Goals (MVP)

- LLM compression
- CONTEXT_REFS resolution
- Custom output formats (Markdown, JSON)
- Selective bundling (flags to include/exclude sections)
- Caching

* Plan Notes

Decisions confirmed [2025-01-19]:
1. Output format: plain text with markdown-style headers
2. Parent chain: full content (SPEC, TODO, RULES), not just rules
3. Space-separated property values for multi-file support
4. Soft failures for missing files (resilient bundling)
5. Interactive command outputs to both kill-ring and buffer

Enhancement decisions [2025-01-20]:
6. Dual output modes: paths (default) and text (full content)
7. Naming: =specflow-bundle= (paths), =specflow-bundle-text= (full)
8. Default optimized for Claude Code (can read files directly)
9. NEXT task content included in both modes (typically short)
10. Implementation: shared core logic, two output formatters
