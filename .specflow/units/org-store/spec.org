#+TITLE: org-store – Specification
#+STARTUP: overview

* Purpose

org-store is the foundational SpecFlow module responsible for:
- discovering the control plane file
- parsing project state and unit registry
- reading/writing Org properties with minimal diffs

All other SpecFlow modules depend on org-store.

* Scope

** Owns
- Control plane discovery algorithm
- Reading =SPEC_FLOW_PHASE= and =SPEC_FLOW_ACTIVE_UNIT= properties
- Reading unit entries from the control plane
- Writing property values back to Org files (minimal-diff)
- Validation of required properties

** Does Not Own
- Phase semantics or transitions (core)
- Context bundling (bundle)
- UI/workspace management (hydrate)
- LLM integration (bundle, hydrate)

* Control Plane Discovery

** Algorithm

1. Start from =default-directory= of the current buffer.
2. Search upward for =.specflow/specflow.org=.
3. Stop conditions:
   - File found → return path
   - Reached filesystem root (=/=) → stop searching
   - Reached project root (directory containing =.git=, =.projectile=, or =.specflow-root=) without finding file → stop searching
4. If not found, check =specflow-control-plane-path= variable.
5. If variable is set and file exists → return path.
6. Otherwise → signal error =specflow-control-plane-not-found=.

** Configurable Variable

#+begin_example
(defcustom specflow-control-plane-path nil
  "Explicit path to SpecFlow control plane file.
Used as fallback when automatic discovery fails."
  :type '(choice (const nil) file)
  :group 'specflow)
#+end_example

* Data Structures

All public functions return plists. No structs in MVP.

** Project State

Returned by =specflow-org-store-read-project-state=:

#+begin_example
(:phase "Plan"
 :active-unit "org-store"
 :control-plane-path "/path/to/.specflow/specflow.org")
#+end_example

** Unit Entry

Returned by =specflow-org-store-read-unit=:

#+begin_example
(:name "org-store"
 :dir "src/my_project/org-store/"
 :spec ".specflow/units/org-store/spec.org"
 :todo ".specflow/units/org-store/todo.org"
 :parent "core"
 :children nil
 :context-refs nil)
#+end_example

All paths are relative to project root.

Note: The =:rules= property has been removed. Unit scope and constraints
are now documented in the unit's =spec.org= file.

** Unit Registry

Returned by =specflow-org-store-read-unit-registry=:

#+begin_example
((:name "core" :dir "src/" :spec "..." ...)
 (:name "org-store" :dir "src/" :spec "..." ...)
 ...)
#+end_example

List of unit entry plists in document order.

* Properties

** Required (Hard Failure if Missing)

| Property                | Location         | Description                     |
|-------------------------+------------------+---------------------------------|
| =SPEC_FLOW_PHASE=       | Project heading  | Current phase (Plan, Specify…)  |
| =SPEC_FLOW_ACTIVE_UNIT= | Project heading  | Name of active unit             |
| =SPEC=                  | Unit heading     | Path to unit spec file          |
| =TODO=                  | Unit heading     | Path to unit todo file          |

** Optional (Warning if Missing, Absent = nil)

| Property       | Location     | Description                          |
|----------------+--------------+--------------------------------------|
| =DIR=          | Unit heading | Source directory for unit            |
| =PARENT=       | Unit heading | Parent unit name                     |
| =CHILDREN=     | Unit heading | Space-separated child unit names     |
| =CONTEXT_REFS= | Unit heading | Space-separated advisory file paths  |

* Public API

** specflow-org-store-find-control-plane

#+begin_example
(specflow-org-store-find-control-plane &optional START-DIR)
#+end_example

- Input: =START-DIR= (optional, defaults to =default-directory=)
- Output: Absolute path to control plane file (string)
- Errors: =specflow-control-plane-not-found= if discovery fails

** specflow-org-store-read-project-state

#+begin_example
(specflow-org-store-read-project-state &optional CONTROL-PLANE-PATH)
#+end_example

- Input: =CONTROL-PLANE-PATH= (optional, discovered if nil)
- Output: Project state plist
- Errors:
  - =specflow-control-plane-not-found= if file missing
  - =specflow-control-plane-malformed= if required properties missing

** specflow-org-store-read-unit

#+begin_example
(specflow-org-store-read-unit UNIT-NAME &optional CONTROL-PLANE-PATH)
#+end_example

- Input: =UNIT-NAME= (string), =CONTROL-PLANE-PATH= (optional)
- Output: Unit entry plist
- Errors:
  - =specflow-unit-not-found= if unit not in registry
  - =specflow-unit-malformed= if required properties missing

** specflow-org-store-read-unit-registry

#+begin_example
(specflow-org-store-read-unit-registry &optional CONTROL-PLANE-PATH)
#+end_example

- Input: =CONTROL-PLANE-PATH= (optional)
- Output: List of unit entry plists
- Errors: =specflow-control-plane-malformed= if parsing fails

** specflow-org-store-write-property

#+begin_example
(specflow-org-store-write-property FILE-PATH HEADING-PATH PROPERTY VALUE)
#+end_example

- Input:
  - =FILE-PATH=: Absolute path to Org file
  - =HEADING-PATH=: List of heading titles (e.g., =("Project")= or =("Units" "org-store")=)
  - =PROPERTY=: Property name (string, e.g., "SPEC_FLOW_PHASE")
  - =VALUE=: New value (string)
- Output: =t= on success
- Errors:
  - =specflow-heading-not-found= if heading path invalid
  - =specflow-file-not-writable= if file cannot be saved
- Constraint: Must use minimal-diff write strategy (see below)

** specflow-org-store-validate-unit-pointers

#+begin_example
(specflow-org-store-validate-unit-pointers UNIT-ENTRY &optional PROJECT-ROOT)
#+end_example

- Input: =UNIT-ENTRY= plist, =PROJECT-ROOT= (optional, discovered if nil)
- Output: =t= if all required files (SPEC, TODO) exist
- Errors: =specflow-unit-pointer-invalid= listing missing files

** specflow-org-store-validate-parent-chain

#+begin_example
(specflow-org-store-validate-parent-chain UNIT-NAME &optional CONTROL-PLANE-PATH)
#+end_example

- Input: =UNIT-NAME=, =CONTROL-PLANE-PATH= (optional)
- Output: List of ancestor unit names (e.g., =("core")=)
- Errors: =specflow-parent-not-found= if parent references nonexistent unit

* Interactive Commands

** specflow-phase-shift

#+begin_example
(specflow-phase-shift PHASE UNIT)
#+end_example

- Input:
  - =PHASE= (string, one of: "Plan", "Specify", "Scaffold", "Implement", "Validate", "Document")
  - =UNIT= (string, must be a unit name from the registry)
- Interactive:
  1. Read current phase and active unit from control plane
  2. Prompt for phase with =completing-read= (current phase as default)
  3. Prompt for unit with =completing-read= from unit registry (current unit as default)
- Behavior:
  1. Find control plane via =specflow-org-store-find-control-plane=
  2. Read current state via =specflow-org-store-read-project-state=
  3. Read unit registry via =specflow-org-store-read-unit-registry=
  4. Validate =PHASE= is in allowed list
  5. Validate =UNIT= exists in registry
  6. Write =SPEC_FLOW_PHASE= property to =("Project")= heading
  7. Write =SPEC_FLOW_ACTIVE_UNIT= property to =("Project")= heading
  8. Display confirmation message: "Phase: <PHASE>, Unit: <UNIT>"
- Output: =t= on success
- Errors:
  - =user-error= if =PHASE= is not a valid phase name
  - =user-error= if =UNIT= is not in the unit registry
  - Inherits errors from =specflow-org-store-write-property=

** specflow-add-root-task

#+begin_example
(specflow-add-root-task HEADLINE)
#+end_example

- Input: =HEADLINE= (string, task description)
- Interactive: Prompts for headline string
- Behavior:
  1. Find project root from control plane
  2. Open =.specflow/todo.org=
  3. Find =Backlog= heading (level 1)
  4. Insert =** TODO <HEADLINE>= at end of Backlog section (before next level-1 heading or EOF)
  5. Save file with minimal diff
  6. Display confirmation message: "Task added: <HEADLINE>"
- Output: =t= on success
- Errors:
  - =specflow-heading-not-found= if =Backlog= heading not found in =.specflow/todo.org=
  - =specflow-file-not-writable= if =.specflow/todo.org= cannot be saved

** specflow-refine-task

#+begin_example
(specflow-refine-task)
#+end_example

- Input: None (all input gathered interactively)
- Interactive:
  1. Prompts with =completing-read= to select a task from Backlog section
  2. Prompts for related unit (optional, free text, RET to skip)
  3. Prompts for additional context/instructions for Claude
- Behavior:
  1. Find project root from control plane
  2. Read =.specflow/todo.org= and parse Backlog section for level-2 headings
  3. Display task headlines via =completing-read=
  4. Prompt for optional unit hint
  5. Prompt for user context/instructions
  6. Generate prompt with task text (headline + body), unit hint, user context, and guidelines
  7. Copy prompt to kill-ring
  8. Display confirmation message: "Task prompt copied to kill-ring"
- Output: Generated prompt string (also in kill-ring)
- Note: This command does NOT modify =.specflow/todo.org=. The generated prompt instructs Claude to make the changes.
- Prompt Format:
  #+begin_example
  ## Task to Refine

  <task headline and body from todo.org>

  ## Context

  Related unit: <user input or "Not specified">
  Notes: <user's additional context>

  ## Guidelines

  Rewrite this task to be actionable and outcome-based:
  - Use Given/When/Then format where appropriate
  - Be specific about expected outcomes
  - If unit placement is unclear, recommend where it should live
  - Keep it concise (3-5 bullets max)

  Refine this task and update it in =.specflow/todo.org=.
  #+end_example
- Errors:
  - =specflow-heading-not-found= if =Backlog= heading not found in =.specflow/todo.org=

** specflow-activate-task

#+begin_example
(specflow-activate-task)
#+end_example

- Input: None (all input gathered interactively)
- Interactive: Same as =specflow-refine-task=
- Behavior:
  1. Find project root from control plane
  2. Read =.specflow/todo.org= and parse Backlog section for level-2 headings
  3. Display task headlines via =completing-read=
  4. Prompt for optional unit hint
  5. Prompt for user context/instructions
  6. Generate prompt with task text (headline + body), unit hint, user context, and guidelines
  7. Copy prompt to kill-ring
  8. Display confirmation message: "Task prompt copied to kill-ring"
- Output: Generated prompt string (also in kill-ring)
- Note: This command does NOT modify =.specflow/todo.org=. The generated prompt instructs Claude to make the changes
  (move task to Active as NEXT, demote existing NEXT to TODO).
- Prompt Format: Same as =specflow-refine-task=, with additional instruction:
  #+begin_example
  After refining, move this task from Backlog to Active section as NEXT.
  If there is an existing NEXT task in Active, demote it to TODO.
  #+end_example
- Errors:
  - =specflow-heading-not-found= if =Backlog= heading not found in =.specflow/todo.org=

** Difference between refine-task and activate-task

Both commands generate a prompt and copy it to kill-ring. Neither modifies =.specflow/todo.org= directly.
The difference is in the prompt instructions given to Claude:

| Aspect | specflow-refine-task | specflow-activate-task |
|--------|---------------------|------------------------|
| Prompt | Yes (kill-ring) | Yes (kill-ring) |
| Modifies .specflow/todo.org | No | No |
| Prompt instruction | "Refine and update in .specflow/todo.org" | "Refine, move to Active as NEXT, demote existing NEXT" |
| Message | "Task prompt copied to kill-ring" | "Task prompt copied to kill-ring" |

* Error Handling

** Hard Failures (signal error)

| Error Symbol                       | Condition                                      |
|------------------------------------+------------------------------------------------|
| =specflow-control-plane-not-found= | Discovery failed and no fallback configured    |
| =specflow-control-plane-malformed= | Required project properties missing or invalid |
| =specflow-unit-not-found=          | Requested unit not in registry                 |
| =specflow-unit-malformed=          | Unit missing required properties               |
| =specflow-unit-pointer-invalid=    | SPEC/TODO file does not exist                  |
| =specflow-parent-not-found=        | PARENT references nonexistent unit             |
| =specflow-heading-not-found=       | Write target heading not found                 |
| =specflow-file-not-writable=       | Cannot save file                               |

** Warnings (message, do not fail)

| Condition                        | Behavior                         |
|----------------------------------+----------------------------------|
| Optional property missing        | Return =nil= for that key        |
| =CONTEXT_REFS= file not found    | Log warning, include path anyway |

* Minimal-Diff Write Strategy

When writing a property value:

1. Open file in temporary buffer (do not visit).
2. Navigate to target heading using =HEADING-PATH=.
3. If property drawer exists:
   - If property exists: replace value in-place (preserve whitespace alignment if reasonable)
   - If property missing: insert new property at end of drawer
4. If no property drawer: create one with single property.
5. Write buffer to file.
6. Do NOT reformat, re-indent, or modify any content outside the property drawer.

** Invariant

Running =specflow-org-store-write-property= followed by reading the same property
must return the written value. No other file content may change (byte-for-byte
outside the modified property line).

* Caching

No caching in MVP. Every read function re-reads from disk.

Rationale: Determinism and simplicity. Caching may be added later with explicit
invalidation hooks.

* Testing Requirements

** ERT Test Coverage

- Discovery: file found at various depths, fallback to variable, error on not found
- Project state: valid parse, missing =SPEC_FLOW_PHASE=, missing =SPEC_FLOW_ACTIVE_UNIT=
- Unit read: valid unit, missing unit, missing required properties
- Unit registry: multiple units, empty registry
- Write property: existing property, new property, new drawer, heading not found
- Validation: valid pointers, missing files, parent chain valid, parent not found
- Phase shift: valid phase change, invalid phase rejected, confirmation displayed
- Add root task: task added to Active section, missing Active heading error, confirmation displayed
- Refine task: lists backlog tasks, handles empty unit input, generates correct prompt format, copies to kill-ring, moves task to Active as TODO, prompt ends with edit instruction
- Activate task: demotes current NEXT, moves task to Active as NEXT, handles no existing NEXT, prompt ends with edit instruction

** Determinism Tests

- Read same file twice → identical output
- Write property twice with same value → no file change on second write
- Write property → read property → value matches

* Non-Goals

- Caching (deferred to later version)
- Async/concurrent access
- Multiple control planes per repo
- Org-element full AST manipulation (use targeted parsing only)
- Phase transition logic (owned by core)
