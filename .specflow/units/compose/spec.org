#+TITLE: compose – Specification
#+STARTUP: overview

* Purpose

=compose= generates task-specific prompts for AI assistants.

It complements =hydrate=:
- hydrate = continue workflow (generic conversation header with current state)
- compose = start new task (task-specific prompt with requirements and instructions)

Target user: Developer using SpecFlow who wants to initiate a new task with Claude.

* Scope

**In scope**
- Generate prompts for common SpecFlow workflows
- Provide guided template buffers for gathering requirements
- Include context files and phase-appropriate instructions in output
- Instruct Claude to preserve planning artifacts

**Out of scope**
- Executing tasks (compose generates prompts, Claude executes)
- Direct file editing
- LLM integration (user manually pastes prompts)
- Phase transitions (user updates control plane manually)

* Public Commands

** specflow-compose (dispatcher)

Interactive command that presents a menu of available compose actions.

#+begin_example
What do you want to do?
[1] Create new unit
[2] Edit specification
[3] Add new feature
[4] Refactor code
#+end_example

Single keypress selects action, opens corresponding template buffer.

** specflow-compose-new-unit

Generate prompt for creating a new SpecFlow unit.

| Question | Required | Default |
|----------+----------+---------|
| Unit name | Yes | — |
| Parent unit | Yes | core |
| Purpose (one line) | Yes | — |
| Problem it solves | Yes | — |
| In scope | Yes | — |
| Out of scope | No | — |
| Dependencies | No | — |
| Key commands/functions | No | — |

** specflow-compose-edit-spec

Generate prompt for editing a unit's specification.

| Question | Required | Default |
|----------+----------+---------|
| Which unit | Yes | active unit |
| What to change | Yes | — |
| Why (rationale) | Yes | — |
| Constraints | No | — |

** specflow-compose-new-feature

Generate prompt for adding a feature to an existing unit.

| Question | Required | Default |
|----------+----------+---------|
| Which unit | Yes | active unit |
| Feature description | Yes | — |
| In scope | Yes | — |
| Out of scope | No | — |
| Affects parent architecture? | Yes | Unsure |

** specflow-compose-refactor

Generate prompt for refactoring code.

| Question | Required | Default |
|----------+----------+---------|
| Which unit | Yes | active unit |
| What to refactor | Yes | — |
| Why (rationale) | Yes | — |
| Constraints | No | — |

* Template Buffer Format

All compose commands open an Org-mode buffer with this structure:

#+begin_example
#+TITLE: <Task Type>

* <Question 1>
<user types answer here>

* <Question 2>
<user types answer here>

...

────────────────────────────────────────
C-c C-c  Generate prompt and copy to kill-ring
C-c C-k  Cancel
#+end_example

*** Keybindings

| Key | Action |
|-----+--------|
| =C-c C-c= | Generate prompt, copy to kill-ring, show in buffer |
| =C-c C-k= | Cancel and kill template buffer |

*** Buffer Behavior

- Buffer is created with a minor mode: =specflow-compose-mode=
- Headings are read-only (questions)
- User types under each heading
- Empty required fields trigger warning on generate

* Generated Prompt Format

All generated prompts follow this structure:

#+begin_example
## Task: <task description>

### Current State
- Active unit: <unit>
- Phase: <phase>
- Parent chain: <chain or "none">

### Context Files
Read these files for context:
- <file1> (<description>)
- <file2> (<description>)
...

### Requirements
<structured requirements from user answers>

### Instructions
<task-specific step-by-step instructions>

### Phase Rules
<phase-appropriate constraints>

### Artifact Preservation
Save planning discussions and design decisions to:
  units/<unit>/temp-planning-artifacts.org

This preserves context across sessions. Delete after official docs are finalized.

### Phase Completion Checklist

When this phase is complete:

1. Update .specflow/todo.org:
   - Mark current NEXT as DONE with summary
   - Create new NEXT for next phase

2. Update control plane (.specflow/specflow.org):
   - Change SPEC_FLOW_PHASE to next phase

3. Commit: "<unit>: complete <phase> phase"
#+end_example

* Phase Completion Instructions

All generated prompts MUST include phase completion instructions.

The instructions are dynamic based on the current phase and unit name:
- Unit name is interpolated into the .specflow/todo.org entry format
- Phase name is interpolated into the entry and commit message
- Next phase is computed from current phase (Plan→Specify, etc.)
- If current phase is Document, instructions note "unit complete"

* Context File Selection

Each command includes relevant context files:

| Command | Context Files |
|---------+---------------|
| new-unit | architecture.org, .specflow/specflow.org, .specflow/todo.org |
| edit-spec | unit spec.org, parent spec(s), .specflow/specflow.org |
| new-feature | unit spec.org, unit todo.org, parent spec(s) |
| refactor | unit spec.org, relevant source files |

* Phase Enforcement

Compose commands require **Plan** phase.

If current phase is not Plan:
1. Display error message
2. Suggest running =specflow-set-phase= (if available) or manual update
3. Do not open template buffer

Error message:
#+begin_example
compose-new-unit requires Plan phase.
Current phase: <phase>
Update control plane to Plan phase before composing new tasks.
#+end_example

* Workflow Direction (new-feature)

=specflow-compose-new-feature= asks:

> "Does this feature require changes to parent unit architecture?"

| Answer | Behavior |
|--------+----------|
| Yes | Include parent context, instruct to start from parent |
| No | Include only child context, work in child unit |
| Unsure | Include both, instruct Claude to determine starting point |

* Artifact Preservation Requirement

All generated prompts MUST include the "Artifact Preservation" section instructing Claude to:

1. Save planning discussions to =temp-planning-artifacts.org= in the unit directory
2. Use Org format with dated sections
3. Capture design decisions, Q&A, rationale
4. Note that artifacts are temporary and deleted after official docs finalized

This ensures context is preserved across:
- Session boundaries
- Context window compaction
- Handoffs between conversations

* Dependencies

- =org-store=: Read control plane, project state, unit info
- No dependency on =hydrate= or =bundle=

* Error Handling

| Condition | Behavior |
|-----------+----------|
| Not in Plan phase | Error message, do not proceed |
| Control plane not found | Signal =specflow-control-plane-not-found= |
| Unit not found | Signal =specflow-unit-not-found= |
| Required field empty | Warning, allow generate with placeholder |
| Context file missing | Include path with "(not found)" note |

* Non-Functional Requirements

- *Fast*: Template buffer opens immediately
- *Clean*: Minimal UI, familiar Org interface
- *Deterministic*: Same inputs produce same prompt (modulo timestamps)
- *No side effects*: Compose only generates text, never writes files

* Success Criteria

Given a developer wants to create a new unit,
when they run =specflow-compose-new-unit= and fill in the template,
then the generated prompt contains:
- All their requirements
- Correct context files for the task
- Phase-appropriate instructions
- Artifact preservation instructions

And they can paste it into Claude and receive a properly structured response.
