---

* Hierarchy Semantics

Units may form a **conceptual hierarchy**.

Hierarchy is:
- informational and organizational
- used for planning, navigation, and context bundling
- NOT a runtime dependency

Hierarchy is declared via optional properties:
- `PARENT`
- `CHILDREN`

Semantics:
- Parent unit specs define higher-level constraints for child units
- When working on a unit, parent specs should be reviewed first
- Child units must not redefine parent-level invariants
- Hierarchy does not imply code-level coupling

Tools and AI assistants may use hierarchy to:
- assemble contextual bundles
- guide planning vs implementation
- surface architectural intent
